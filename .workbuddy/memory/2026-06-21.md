## 防御性重构：代码兼容缺少 can_post/can_reply 的旧数据库（2026-06-21 第二次会话）

### 问题
用户部署到服务器后管理员界面仍无法跳转，分析确认：/api/me 查询 can_post/can_reply 列 → 旧数据库列不存在 → SQL 500 错误 → checkAdmin() 静默跳回登录页。

### 修复（app.py）
- `/api/me`：SELECT can_post,can_reply 用 try/except 包裹，异常时默认 can_post=1, can_reply=1
- `create_topic`：SELECT can_post 用 try/except 包裹，异常时允许发帖
- `create_post`：SELECT can_reply 用 try/except 包裹，异常时允许回复
- `admin_users`：查询用 try/except，异常时回退到不查这些列的 SQL
- `restrict_user`：UPDATE 用 try/except，异常时返回友好错误提示

### 修复（admin.html）
- `checkAdmin()` 不再静默跳转：HTTP 错误弹 alert 提示；未登录跳 /login；非管理员跳 /；网络异常弹 alert

### 测试验证
- 模拟无 can_post/can_reply 列的旧数据库：init_db 迁移成功添加列，所有接口（/api/me, create_topic, create_post, admin_users）均正常通过
- 真实数据库全链路：Login → /api/me → /api/admin/stats → /api/admin/users → /api/topics 全部 200 OK
- 服务器已重启（PID 3104，本地 5001 端口）
