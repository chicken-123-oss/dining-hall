# 2026-06-18 工作日志

## 优化封禁申诉系统 + 新增功能性限制

### 问题
1. 被封禁用户无法登录，申诉页需要登录才能显示用户名，形成死循环
2. 管理员只能"完全封禁"用户，没有部分功能限制选项

### 修改内容

#### login.html
- 登录失败时若 `data.banned === true`，在消息框显示"账号已被封禁"并附带可点击的申诉链接
- 链接目标：`/appeal?username=<用户名>`，XSS 安全（用 DOM 操作而非 innerHTML）

#### appeal.html
- 去掉 `appealUsername` input 的 `readonly` 属性
- `initUsername()` 优先级：URL参数 → /api/me → localStorage → 留空并提示手动输入
- 去掉"找不到用户信息就跳转登录"的逻辑

#### app.py
- `init_db()` 新增迁移：`ALTER TABLE users ADD COLUMN can_post INTEGER DEFAULT 1` 和 `can_reply`
- `/api/me` 返回 `can_post` 和 `can_reply`
- `create_topic` 检查 `can_post == 0`，返回 403 + 提示
- `create_post` 检查 `can_reply == 0`，返回 403 + 提示
- `/api/admin/users` 查询添加 `COALESCE(u.can_post, 1)` 和 `COALESCE(u.can_reply, 1)`
- 新增 `POST /api/admin/users/<uid>/restrict`，接收 `{can_post, can_reply}`

#### admin.html
- `renderUsers` 状态列显示"限发帖"/"限回复"徽章
- 操作列添加"限制"按钮（黄色样式）
- 新增"功能限制 Modal"，含两个 checkbox
- 新增 `openRestrictModal` / `closeRestrictModal` / `submitRestrict` JS 函数
- 键盘事件支持限制 Modal 的 Escape 和 Enter

### 关键逻辑
- **完全封禁**（banned=1）：无法登录，登录界面显示申诉链接
- **功能限制**（can_post=0 / can_reply=0）：仍可登录，但操作时 API 返回 403 错误
- 两者独立，可同时设置
